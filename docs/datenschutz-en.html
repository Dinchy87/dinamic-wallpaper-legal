Privacy Policy

2. Installation identifier, favorites and downloads

The reviewed iOS implementation creates a random UUID called installation_id and stores it in the app's local settings (UserDefaults). It is a persistent installation identifier, not the Apple advertising identifier in the reviewed event format. Associated records are not fully anonymous.

Favorite identifiers and timestamps are stored locally. When a favorite is added or removed, the app sends an action with the wallpaper ID and installation identifier to the Supabase Edge Function wallpaper-engagement. After successfully saving a wallpaper to the iOS photo library, the app also transmits a download event with an event ID.

Events awaiting confirmation remain in a local queue and are retried later. The reviewed server function stores favorites with wallpaper ID, installation identifier and server timestamp. Downloads also include an event ID and an internal record ID. Removing a favorite deletes the corresponding favorite record. These records contribute to overall popularity rankings. A separate favorite counter without installation linkage has not been implemented.

Before release: Establish and verify the appropriate legal basis for each activity, the legitimate-interest assessment where applicable, the need for consent and the means to object.

3. Image retrieval and local storage

The app retrieves catalog data from Supabase. When an image variant is not available in its local cache, it requests a signed link through wallpaper-image-url using a wallpaper ID and variant, then downloads the file. The reviewed server function generates Cloudflare R2 image URLs valid for five minutes. Expiry of a URL does not delete already downloaded files. Image files are cached locally.

To save images, the app requests the iOS permission to add photos. Sharing uses the native iOS share sheet; further processing depends on the chosen receiving app.

4. Service providers and technical connection data

Supabase provides the catalog and app endpoints, and Cloudflare R2 provides image storage. Reviewed Supabase log fields include IP address, requested URL, device/browser metadata and approximate region inferred from the connection. Binding retention periods for technical logs have not yet been confirmed.

The Supabase project is located in eu-west-1 and the R2 bucket is configured for Western Europe (WEUR). The R2 public development endpoint and additional Data Access Logs are disabled. These settings do not rule out all processing outside the EU.

Supabase indicates its data processing addendum is incorporated in the applicable agreement. Cloudflare's self-service terms also address data processing terms.

Before release: Confirm the applicable contracting entities, controller/processor roles, subprocessors, international transfer safeguards and the required assessment under GDPR Articles 44 et seq.

5. This website

This static website is hosted on GitHub Pages. Its source does not embed analytics scripts, third-party fonts or cookies, and does not transmit the app installation identifier. GitHub receives technical connection data when delivering pages. See GitHub's privacy statement.

Before release: Confirm the hosting entities and roles, legal basis, actual access logs, retention periods and any applicable international data transfers.

6. Support requests

Support and privacy requests may be emailed to dinamicwallpaper@outlook.com. The mailbox is provided through Microsoft Outlook.com. Sender and contact details, message content and any attachments provided are processed to respond to the request. Please include only necessary information.

Before release: Verify the applicable Microsoft entity and role, legal basis, transfer provisions and retention/deletion periods for correspondence.

7. Retention and deletion

The reviewed client code does not impose an automatic expiry on its installation identifier or local favorites. Confirmed events are removed from the local pending queue. Removing a favorite deletes its server favorite record, but does not establish deletion from every log or backup. No automatic cleanup of old download events was found in the reviewed server functions or database rules. A 30-day popularity reporting window is not a deletion period. Complete deletion of installation-related records has not been tested end-to-end.

Before release: Define retention periods or criteria for events, identifiers, logs, cached images, correspondence and backups; verify a practical deletion request procedure. App uninstallation must not be described as automatic server-side erasure.

8. Your rights

Subject to the requirements of the GDPR, you may have rights of access, rectification, erasure, restriction, portability and objection. Consent, where used, may be withdrawn for the future. You may lodge a complaint with a data protection supervisory authority.

Before release: Determine whether a data protection officer must be named; identify the competent supervisory authority as appropriate and verify information about mandatory data provision and automated decision-making.

9. Review status

The review is based on selected iOS source files and project documentation, together with read-only checks of app Edge Functions, database structures, sample log field names and R2 settings. It is not a complete review of every SDK, contract or the final App Store build. Features such as advertising, tracking, accounts or in-app purchases must be checked against the release build.

Reference: GDPR, especially Article 13. This draft still contains outstanding mandatory information and is not yet the final policy.
